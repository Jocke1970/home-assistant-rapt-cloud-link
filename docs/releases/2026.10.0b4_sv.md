# RAPT Cloud Link 2026.10.0b4 – Aktiv RAPT-profil observerad vid API-poll

**Kanal:** GitHub Pre-release / HACS beta
**Manifest:** `2026.10.0b4` · **tagg efter beta-merge:** `v2026.10.0b4`
**SOP:** dev → beta → main; main oförändrad.

## Åtgärd
- BrewZillas RCL-profilsensor exponerar `profile_observed_at`, en tidsstämpel från den senaste **lyckade anslutna API-pollen med aktiv profil**.
- Samma RAPT-profilsteg får vara oförändrat i flera minuter, även när RCL pollar framgångsrikt. Därför får BA inte använda oförändrad HA `last_updated` som bevis för gammal profil.
- Saknad anslutning, API-fel, saknad/otydlig enhet eller inaktiv profil skapar **inte** en ny giltig observation.
- Verifierad STOP kräver fortfarande två separata rena polls; kommunikationsbortfall är aldrig STOP.

## Test och installation
- Isolerade Python-regressionstester, HACS och Hassfest måste vara gröna på exakt versionssatt candidate samt på beta-merge-SHA.
- Efter beta-merge: skapa NY tagg `v2026.10.0b4` på beta-merge-SHA och ny GitHub **Pre-release**. Återanvänd inte b3-taggen. Release får inte vara Latest/stable.
- Uppdatera via HACS (prereleases aktiverat), starta om Home Assistant och kontrollera RCL Profile Active-attributet `profile_observed_at`.
- Kontrollera att tidsstämpeln förnyas vid lyckad RCL-poll under oförändrat Mash Out-steg; utebliven poll ska ge ökande ålder.
- Uppdatera därefter BrewAssistant b8 och dess fullständiga RAPT Profile Runtime-Lovelace-kort för att nyttja attributet.

Ingen ny actuator-tjänst, inga heat/pump/target-skrivningar och inga automatiska profilbyten. Vattenprov och fysisk STOP/readback krävs före main.
